# ATM Town v235.11.7 — Mobile Store Width Lock

This patch fixes the remaining narrow-phone Attribute Store overflow that could push the **Review Payment** CTA beyond the visible right edge.

## Root layout problem

The mobile cart and CTA were still participating in the same responsive Store body that owns the scrolling catalog. Repeated `width:100%` constraints did not isolate the CTA from the catalog's layout width, so a narrow viewport could still render the cart action wider than the visible Store card.

## Fix

- On mobile, the Store body becomes a bounded positioning context.
- The cart becomes an inset bottom action bar using `left: 0` + `right: 0` and `width: auto`.
- The Review Payment button fills that already-bounded cart with flex centering instead of defining its own viewport-relative width.
- Phone catalogs are forced to one column; larger mobile/tablet layouts use two columns.
- Every relevant Store/catalog/item container is explicitly shrinkable and horizontally clipped.
- Catalog space is reserved above the cart so the bottom products remain scrollable and tappable.

The dedicated payment sheet from v235.11.6 remains the checkout surface. Store crypto purchases are still XRPL Mainnet (ATM, RLUSD, XRP) to the configured merchant wallet. World-event funding/rewards remain Testnet.
