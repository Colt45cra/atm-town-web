# ATM Town v235.3 — Payload Money Rain

ATM Town v235.3 connects the World Event Engine to Project Payload v0.2.1 for the first reward-enabled Money Rain proof on XRPL Testnet.

## Scope

This release intentionally enables **Testnet XRP only**. Payload remains asset-generic, but issued-token funding adds issuer/trust-line and two-stage network-funding requirements that should be tested separately after the XRP path is proven.

No new ATM Town Supabase migration is required. The existing `world_events.config` JSON stores the Payload campaign and settlement state.

## Sponsor flow

1. The sponsor opens the ATM Command Core inside HQ.
2. The sponsor chooses the displayed provider identity and a Testnet XRP prize pool.
3. ATM Town's server creates a unique campaign through Payload's signed Integration API.
4. Payload returns a unique temporary campaign execution wallet and the total required funding amount.
5. The sponsor reviews the prize pool and total funding requirement.
6. The sponsor authorizes **one** exact Testnet XRP funding Payment with the ATM Town embedded wallet.
7. The XRPL seed/private key is decrypted only on the user's device for that signing operation, then discarded from memory. The seed/private key is never sent to ATM Town's server or Payload.
8. ATM Town relays only the already-signed transaction blob.
9. Money Rain starts only after Payload confirms the full campaign funding amount.

If submission/confirmation becomes uncertain after signing, ATM Town stores the immutable signed transaction hash/blob locally and changes the action to **CHECK FUNDING & START**. It never silently creates a second funding signature. The same signed blob can be safely re-submitted because it authorizes only the already-reviewed destination, amount and memo.

## Reward math

Money Rain still has exactly 1,000 server-authoritative game points. A reward pool must be between **0.001 and 5 Testnet XRP**, in **0.001 XRP increments**. This guarantees that one game point always maps to an exact integer number of XRP drops.

Examples:

- 0.100 XRP pool → 100 drops per point
- 1 XRP pool → 1,000 drops per point
- 5 XRP pool → 5,000 drops per point

Every accepted server-side pickup is preserved. First place is a leaderboard rank only. Each participant receives:

`verified points collected × reward drops per point`

A player must have an ATM Town embedded **Testnet** wallet to collect from a reward-enabled Money Rain. This prevents an event from finishing with a winner who has no verified settlement destination.

## Payload settlement

At event completion ATM Town:

1. resolves each collecting user's verified embedded Testnet wallet server-side;
2. registers all final participants with Payload;
3. constructs the exact per-wallet distribution;
4. computes the same canonical result hash Payload computes;
5. locks the immutable result package in Payload;
6. asks Payload v0.2.1 to execute its resumable distribution; and
7. continues settlement on later World Event polls until Payload reports completion.

Payload persists signed payout transactions before broadcast and resumes around successful recipients instead of paying them twice. Any campaign XRP not required for player payouts, network fees and cleanup is returned to the sponsor's verified Testnet refund wallet by Payload.

## Custody boundary

The sponsor's main ATM Town wallet remains non-custodial. Payload temporarily controls only the XRP deliberately deposited into the unique campaign wallet. The sponsor's seed is never copied into Payload.

Payload's current campaign wallet uses its existing encrypted server-side execution-seed model. This is acceptable for the Testnet proof. Mainnet should require a dedicated signer security review and stronger isolation/HSM/MPC or equivalent controls before activation.

## Safety limits for this phase

- XRPL network: Testnet only
- Reward asset: XRP only
- Prize pool: 0.001–5 XRP
- Prize-pool increment: 0.001 XRP
- Maximum Payload campaign funding ATM Town will authorize: 25 Testnet XRP
- Maximum registered recipients: 100
- Maximum funding transaction fee: 0.01 XRP
- Funding transaction expiration: 20 ledgers
- Existing Vercel Hobby serverless API count remains 12

## Required Production environment

ATM Town Vercel Production must contain:

- `PAYLOAD_API_BASE_URL`
- `PAYLOAD_INTEGRATION_PRIVATE_KEY_PKCS8_B64`

The private integration key is server-only. It must never be exposed in browser configuration, committed to Git, logged, or returned by an API.

Payload must have ATM Town's matching Ed25519 public integration key registered under the `atm_town` integration client and Payload v0.2.1 must be deployed on XRPL Testnet.

## Preserved preview mode

The original World Event preview remains available as **START PREVIEW · NO XRP**. Preview events use the same visual storm and server-authoritative pickup system but do not create, fund, or execute a Payload campaign.
