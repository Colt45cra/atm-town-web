# ATM Town v234.2.4 — ATM Pay Mobile RPC Reliability

## Purpose

ATM Pay no longer depends on the Ripple Testnet WebSocket endpoint on port 51233. Some mobile, carrier, firewall, and captive networks can time out non-standard WebSocket ports even when ordinary HTTPS works.

## Browser settlement transport

ATM Pay now uses HTTPS JSON-RPC directly from the browser for public XRPL network operations. Local signing is unchanged: the XRPL seed is decrypted only for the signing operation and never leaves the device.

The browser endpoint pool is attempted in order:

1. `https://testnet.xrpl-labs.com/`
2. `https://testnet.honeycluster.io/`
3. `https://s.altnet.rippletest.net:51234/`

Payment preparation reads account sequence and live fees through JSON-RPC. The signed `tx_blob` is submitted directly to Testnet through JSON-RPC, then ATM Town polls the transaction hash until it is validated or its `LastLedgerSequence` expires.

## Server verification transport

ATM Town server-side balance and post-ledger verification now share `lib/xrpl-testnet-rpc.js`, which uses the same resilient endpoint pool. `XRPL_TESTNET_RPC_URL` remains an optional first-choice override for a future dedicated provider.

## Custody boundary

No wallet seed or private key is sent to ATM Town. The ATM Town API does not accept or relay signed transaction blobs. XRPL settlement remains client-signed and client-submitted.

## Safety retained

- Testnet only.
- 10 XRP per-payment Testnet cap.
- Fee ceiling remains 0.01 XRP.
- Fresh wallet authorization per payment.
- Server-bound ATM Pay intent and XRPL memo binding.
- Sequence and ledger-expiration checks immediately before signing.
- Submitted transaction hash is persisted before network broadcast.
- Server independently verifies the final validated transaction.
