# ATM Town v235.11 — Attribute Store Foundation

## Scope

This update separates **ownership** from **shopping**. The Locker now renders only items the player currently owns. Unowned modular attributes are browsed in the new Attribute Store.

## Main-screen entry

A shopping-cart button sits directly below the Locker button. It opens the Attribute Store without changing the world map or existing gameplay systems.

## Character catalogs

The store builds its character tabs from `ATM_ITEM_CATALOG`. Equipment is assigned to a character catalog using `compatibleCharacterIds` (or `storeCharacterIds` when a future item needs a separate commerce mapping). Current ATM modular equipment is therefore shown under ATM. Every playable character already gets a catalog tab, including Bear; characters that do not yet have modular attribute layers show an empty-catalog message rather than borrowing ATM assets.

## Attribute filters

The store supports All, Body, Chest, Face, Head, Backpack, Katana, Gloves, Shoes and Utility filters. A SHOW selector lets the player view Buyable, All or Owned items. NFT-owned items are marked owned and cannot be added to the cart.

## Locker rule

`lockerVisibleItems()` now filters by `lockerOwnershipInfo(item).owned`. Unowned store assets are not rendered in the Locker character builder or inventory. An empty Locker category provides a direct Attribute Store button.

## Payments / prices

`ATM_TOWN_CONFIG.attributeStore` defines a commerce policy object. v235.11 deliberately ships with checkout disabled and no invented item prices. The permanent payment method list is:

- XRP (XRPL)
- ATM (XRPL)
- RLUSD (XRPL)
- USD (card rail)

This preserves the product requirement that XRP, ATM and RLUSD remain available even after non-crypto USD/card checkout is added. Cart state is local convenience data only; **purchase ownership must never be granted from localStorage**. Live checkout must write and verify permanent purchase entitlements server-side before the Locker treats an item as purchased.
