# ATM Town v235.12.5 — Prop Hunt Seeker Hotfix

## Fixes

### Startup ReferenceError

The v235.12.4 town depth renderer passed `sessionId:id` into the Prop Hunt remote-player render hook after the `for (const [id,p] of remotePlayers)` loop had already ended. That made `id` undefined inside the later sorted render pass and could stop ATM Town with:

`Uncaught ReferenceError: id is not defined`

v235.12.5 stores the remote session id directly on the queued depth item and later passes `item.id` into the Prop Hunt renderer.

### Found props become seekers

Prop Hunt now follows the intended chain-hunt rule:

1. One player starts as the original hunter.
2. Everyone else is a disguised prop.
3. When a prop is tagged, that player returns to their normal character.
4. That player becomes a **Seeker** and can tag remaining hidden props.
5. Every subsequent found prop joins the seeker team.
6. The hunt continues until the final hidden prop is actually tagged.
7. The **last prop found wins**.

## Server state

The existing `found_session_ids` list doubles as the converted-seeker roster. Public Prop Hunt state also exposes `seeker_session_ids` containing the original hunter followed by all found players.

No SQL change is required because Prop Hunt state continues to live inside the existing `world_events.config` JSON object.

## Testing

1. Load ATM Town with two or more players online and confirm the game starts normally.
2. Start Prop Hunt from the HQ World Event Control.
3. Confirm one player is the original hunter and other participants use the real map-item disguises.
4. After the hide phase, tag one disguised player.
5. Confirm the tagged player returns to their normal character and their HUD role becomes `SEEKER`.
6. Confirm that new seeker can also see/use `TAG` on a remaining hidden prop.
7. Repeat until the final prop is tagged.
8. Confirm the final tagged prop is announced as the winner.
9. Confirm all clients agree on the same remaining-prop count and winner.
