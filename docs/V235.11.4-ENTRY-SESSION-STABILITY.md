# ATM Town v235.11.4 — Entry Session Stability

This patch fixes intermittent mobile access-flow reentry after passkey login / Enter Town.

## Root causes addressed

1. The landing Log In button could launch overlapping passkey requests because only the hidden/secondary passkey control was disabled. A late completion could reopen the known-account profile after multiplayer had already entered.
2. The Enter Town control had both `click` and touch `pointerup` bindings. The click path alone is now authoritative.
3. Successful multiplayer entry left the Enter Town button disabled. If stale DOM/access-flow state was restored, the player could be trapped on an unclickable Enter Town screen.
4. Service-worker `controllerchange` forcibly reloaded every already-controlled page during a deploy. Active players could be thrown back to the landing flow. Updates now take effect on the next natural navigation instead.
5. Xaman resume checks may continue in the background, but cannot reopen signup over an active town session.

No multiplayer protocol, world-event Testnet/Mainnet policy, Attribute Store payment policy, or character/equipment behavior is changed.
