# ATM Town v235.5 — ATM Pay Testnet Wallet Reset

## Purpose

Adds a dedicated, explicit recovery path for an ATM Town user who can no longer unlock the existing embedded XRPL Testnet wallet and therefore needs a brand-new Testnet wallet without creating a new ATM Town account or losing the existing ATM Pay @handle.

## Security boundaries

- Testnet only. This route does not enable Mainnet wallet replacement.
- The replacement XRPL keypair is generated locally in the browser with `xrpl.Wallet.generate()`.
- The plaintext seed is encrypted locally with the same AES-GCM vault model used by normal ATM Pay wallet creation.
- Only the new public address and encrypted backup are sent to ATM Town.
- The normal `save` route still blocks silent address replacement. Replacement is possible only through the dedicated `reset-testnet-wallet` action.
- The server requires the exact confirmation phrase `RESET TESTNET WALLET`, an explicit loss acknowledgement, the currently attached public address, and a schema-valid encrypted replacement backup.
- The server uses a compare-and-swap style update (`user_id` + current address) so a stale page cannot replace a wallet that changed in another session.
- Pending unsigned ATM Pay intents involving the old routing address are cancelled after replacement. Submitted/validated ledger history is left intact.
- The ATM Pay profile/@handle is not deleted or recreated, so the user's ATM Pay identity is preserved.

## User flow

1. Open ATM Pay.
2. Open **Security**.
3. Under **Testnet wallet reset**, choose **Reset Testnet Wallet**.
4. Review the warning that the old XRPL address remains on-ledger and its Test XRP/assets are not moved.
5. Type `RESET TESTNET WALLET` exactly and acknowledge the warning.
6. ATM Pay generates and encrypts a new Testnet wallet locally.
7. The server atomically replaces only the wallet routing record for the signed-in user.
8. ATM Pay displays the new ATM1 recovery key and offers an encrypted-backup download.
9. After the user confirms the recovery key is saved, the existing ATM Pay @handle resumes on the new address.
10. The new wallet must be funded with Test XRP before ATM Pay or Payload/Money Rain transactions can use it.

## Important limitation

This reset does **not** recover, delete, sweep, or transfer anything from the old XRPL address. If the old wallet later becomes recoverable, its recovery credentials remain the only authority over assets held there.

Before any future Mainnet implementation, wallet replacement should require stronger fresh account reauthentication in addition to destructive-action confirmation.
