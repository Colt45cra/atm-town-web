# ATM Town v235.12 — Commerce + Horde Survival + Neon Racer

## Attribute Store

- Removes the redundant BUYABLE / ALL / OWNED selector. The catalog always shows the selected character/type; owned cards are labeled `NFT OWNED`, `PURCHASED`, or `OWNED` in place.
- Permanent purchases are account entitlements stored in Supabase, not localStorage.
- Store crypto checkout is XRPL **Mainnet** and uses the same merchant destination as Magnet Can vending: `rMSDXpxDpV2pQJDHbp77XHHhT9QHMrfPYB`.
- Initial crypto rails: ATM, RLUSD, XRP.
- Xaman payment requests are server-created. Completion is accepted only after the exact validated Mainnet Payment is checked for payer wallet, destination, InvoiceID, asset/issuer, delivered amount, and `tesSUCCESS`.
- A transaction hash can be used only once. Paid entitlements are idempotently repaired if a transient database error occurs after the payment row is marked paid.
- Cash/card is intentionally staged but not live until a card provider is selected.
- No launch prices are invented by this patch. Checkout becomes enabled per cart only when the server price table contains prices for every selected item/payment asset.
- Attribute Store commerce reuses the existing Xaman vending start/status API routes to keep the Vercel serverless-function count at 12.

### Required Supabase setup

Run `supabase/ATM-Town-v235.12-Attribute-Commerce.sql` once before testing real Attribute Store purchases.

Then populate `public.attribute_store_prices` only with approved launch prices. Each item may have separate USD, ATM, RLUSD, and XRP amounts. USD is shown for familiar price display even while card checkout remains staged.

## Network separation

- Attribute Store purchases: XRPL **Mainnet**.
- Magnet Can purchases: XRPL **Mainnet** (unchanged).
- ATM Pay embedded wallet/world-event funding/rewards: XRPL **Testnet** (unchanged).

## ATM Neon Racer

The previously unused Racing Cabinet in the Arcade now launches **ATM Neon Racer**. It is a three-lane endless neon run: dodge traffic, collect ATM coins, and survive increasing speed. It supports keyboard, touch steering, gamepad input bridging, shared arcade presence, and proximity voice activity state.

## Vending powers

The test-power catalog now includes:

- **Ghost Can / Invisibility** — 30 seconds. Player is translucent and Horde targeting ignores them.
- **Juggernaut Can** — 30 seconds. Horde survival capacity rises from 2 hits to 5 hits while active.
- **Inferno Can** — 30 seconds. The character is surrounded by animated fire and nearby Horde enemies take authoritative radius damage.

These three products remain test-power buttons in this patch, matching the non-Magnet vending products. Magnet Can remains the existing live Mainnet `$ATM` vending purchase.

## Horde player survival

- Normal players are downed after **2 Horde hits**.
- Juggernaut raises the active threshold to **5 hits**.
- Hits have a short invulnerability window so a zombie pile cannot apply many hits in the same frame.
- Downed players cannot walk, jump, jetpack, shoot, or use world interactions.
- A downed character is rendered rotated onto its side and marked `DOWN · REVIVE`.
- A live teammate within revive range receives a `REVIVE` ACTION interaction.
- Revive broadcasts are distance-checked on the receiving client. Horde `player_hit` messages are accepted only from the current elected combat authority.
- Event completion restores the player automatically.
- Invisibility removes a player from Horde AI target selection while active.
- Inferno damage is applied only by the elected Horde authority and then distributed through normal shared zombie snapshots.
