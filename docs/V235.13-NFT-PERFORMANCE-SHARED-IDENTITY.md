# ATM Town v235.13 — NFT Performance + Shared ATM Identity

## XRPL NFT viewer performance

The XRPL ledger remains the ownership source of truth. Presentation metadata is now cached locally on the device so reopening the Locker does not repeatedly resolve the same NFT artwork through IPFS when the token URI has not changed.

Changes:

- metadata cache keyed by NFTokenID and exact on-ledger URI;
- successful metadata cached for 7 days, transient failures for 10 minutes;
- hydration concurrency increased from 4 to 8 workers;
- NFT UI redraws are batched to reduce full-grid rebuild churn;
- IPFS artwork candidates prefer faster gateways before ipfs.io;
- Trade Beacon artwork advances to another candidate after a short timeout instead of waiting forever for a stalled image request;
- an active beacon is refreshed when its NFT metadata becomes available.

The cache contains only public NFT presentation metadata. Ownership is still refreshed from a validated XRP Ledger before entitlement/ownership decisions.

## Shared ATM identity

ATM Town Supabase Auth is the canonical account system for ATM Town and standalone ATM Pay.

The shared database foundation adds encrypted-wallet backup and public-route tables with RLS. Existing standalone ATM Pay encrypted wallet records can be mapped onto the matching canonical ATM Town Auth user without exposing plaintext wallet secrets.

Canonical ATM Pay handles remain in `atm_pay_profiles`. Legacy standalone handles can be preserved as aliases so old contacts continue resolving to the same user.

## Passkey boundary

Account-login passkeys are WebAuthn relying-party bound. The rollout intentionally does not change ATM Town's current RP ID because changing it would invalidate existing passkeys. Standalone ATM Pay retains password/magic-link fallback while a later common-domain rollout can be planned without breaking enrolled users.
