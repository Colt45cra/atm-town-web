# ATM Town v234.2.5 — ATM Pay Seamless Relay

## Goal

Remove direct XRPL network connectivity from the browser payment flow so ATM Pay behaves reliably on ordinary mobile, tablet, carrier, school, and home networks.

## Custody boundary

The XRPL key remains non-custodial:

- The seed/private key is generated and encrypted in the browser.
- Fresh passkey/recovery authorization still happens on the user's device for every payment.
- The completed transaction is signed locally with `Wallet.sign()`.
- ATM Town never receives the plaintext seed/private key.

After signing, ATM Town's authenticated API may receive the **signed transaction blob** for transport to XRPL Testnet. A signed blob contains the already-authorized transaction and signature; it does not contain the private key and cannot be modified without invalidating the signature.

## Payment transport

Browser:

1. Creates an ATM Pay identity/payment intent by user ID / @handle.
2. Requests live Sequence/Fee/LastLedgerSequence from the same-origin ATM Pay API.
3. Reviews the human recipient and amount.
4. Freshly authorizes and signs locally.
5. Records the signed transaction hash first.
6. Sends only the signed blob + hash + intent ID to the same-origin ATM Pay API.
7. Polls the same-origin API for validated finality.

Server:

- Uses `lib/xrpl-testnet-rpc.js` with multiple Testnet RPC fallbacks.
- Prepares live ledger fields.
- Rechecks Sequence/ledger immediately before local signing.
- Relays the signed blob to XRPL Testnet.
- Independently verifies the final validated transaction by hash, including sender, destination, amount, and the unique ATM Pay intent memo.

## Why

The previous browser-direct Testnet transports could be blocked or fail because of mobile carrier/network policy, CORS, DNS, nonstandard ports, or public-node availability. Same-origin ATM Pay API calls avoid those browser-specific transport failures while preserving local signing.

## Security notes

- Testnet-only remains enforced.
- 10 XRP Testnet per-payment cap remains enforced.
- 0.01 XRP fee ceiling remains enforced.
- 60-second review expiry remains enforced.
- The exact human identity + settlement transaction remains digest-bound before signing.
- Wallet addresses remain hidden from the normal ATM Pay UI.
- The server only accepts a bounded hexadecimal signed blob after an intent's local transaction hash has already been recorded.
- Final activity is not marked successful until XRPL returns a validated transaction that matches the stored ATM Pay intent.

No database migration is required for v234.2.5.
