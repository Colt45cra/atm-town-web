# ATM Town v235.11.6 — Dedicated Checkout UX

## Problem
The Attribute Store payment controls were embedded inside the mobile cart area. Repeated CSS width patches did not solve the production clipping because payment controls still participated in the same constrained layout as the catalog/cart. One mobile rule also used `display:grid!important` on the crypto asset container, which could override the `hidden` state.

## Fix
- Removed payment controls from the catalog/cart layout.
- Added a dedicated checkout sheet inside the Attribute Store card.
- Cart now uses a single **REVIEW PAYMENT** action.
- Checkout sheet is width-contained (`100%`, `min-width:0`, `max-width:100%`, `contain:inline-size`) and never shares horizontal sizing with the catalog.
- On mobile, **CASH / CARD** and **CRYPTO** are stacked full-width controls.
- When CRYPTO is selected, **ATM**, **RLUSD**, and **XRP** are stacked full-width controls.
- `[hidden]` payment sections use `display:none!important` so inactive rails cannot leak into the layout.
- The checkout sheet has Back to Shop and Close controls and closes before the Store when Escape/back-dismiss behavior is used.

## Network policy preserved
- Attribute Store crypto purchases: XRPL Mainnet.
- Merchant destination: same wallet used by Magnet Can vending.
- Accepted crypto rails for now: ATM, RLUSD, XRP.
- World-event funding and rewards remain XRPL Testnet.

Live payment submission remains disabled until prices and server-side permanent purchase entitlements are configured.
