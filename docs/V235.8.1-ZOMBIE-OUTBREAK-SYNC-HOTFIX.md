# ATM Town v235.8.1 — Zombie Outbreak Sync Hotfix

This hotfix keeps the v235.8 combat preview mechanics and fixes multiplayer event delivery/visibility.

- The player who triggers a World Event broadcasts a lightweight realtime hint; every connected client immediately refreshes the authoritative `/api/world-time?action=event` state.
- Zombie Outbreak also bootstraps from the current World Event snapshot on load/update, fixing late-join and resume races.
- World Event state refreshes immediately on focus, pageshow, visibility return, and network reconnect.
- Multiplayer player-state broadcasts now include current Zombie Outbreak combat state.
- Remote players in the same outbreak render the correct blaster/Rapid/Spread gun direction.
- Zombie spawn manifest remains server-authored; the outbreak now creates **60 zombies** instead of 28.
- Each zombie hunts the **nearest known player anywhere outdoors in town** rather than stopping pursuit beyond the old 1200 px chase radius. With multiple players, different zombies naturally choose whichever player is nearest to them.
- Zombie HP/movement/kills remain client-local preview behavior until the later authoritative combat service, so exact zombie positions can still diverge slightly between clients under network latency.
- No Supabase schema change is required beyond the v235.8 Zombie Outbreak migration.
