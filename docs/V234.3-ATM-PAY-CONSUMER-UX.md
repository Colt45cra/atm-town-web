# ATM Town v234.3 — ATM Pay Consumer UX

v234.3 keeps the proven v234.2.6 local-signing and Testnet settlement path intact while making ATM Pay feel more like a consumer payment app.

## Added

- ATM Town character thumbnails are used as ATM Pay profile avatars.
- Recent validated recipients appear as quick-pay choices.
- Pending incoming payment requests are surfaced directly on the Send screen.
- A request's **Pay** button prepares the locked request amount immediately and advances to the secure authorization review.
- ATM Pay polls activity while the signed-in game is active and raises in-game notifications for newly received validated payments and new incoming requests.
- The ATM Pay account button shows a pending-request count.
- Multiplayer presence now broadcasts only the player's public ATM Pay identity (user id, @handle, display name, character id, readiness) — never an XRPL address or wallet secret.
- Walking close to another ATM Pay-enabled multiplayer user exposes a **PAY** interaction. Selecting it opens ATM Pay with that player already selected, so no address or username search is needed.
- Successful payments have a clearer animated completion state.

## Security preserved

- XRPL Testnet only.
- The XRPL seed/private key stays encrypted at rest and is decrypted only during fresh authorization for signing.
- The browser signs locally.
- ATM Town relays only the already-signed transaction blob.
- Existing transaction-intent, recipient-route, amount, fee, sequence, expiration, and memo checks remain unchanged.
- Xaman/Mainnet behavior remains separate and unchanged.

## No database migration

v234.3 derives recent recipients and notification state from the existing ATM Pay activity data. No new SQL is required.
