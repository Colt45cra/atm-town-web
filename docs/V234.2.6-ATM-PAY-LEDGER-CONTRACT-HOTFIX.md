# ATM Town v234.2.6 — ATM Pay Ledger Contract Hotfix

## Purpose

Fixes a client/server field-name mismatch in ATM Pay payment preparation.

The authenticated ATM Pay API returns the current XRPL Testnet ledger as `ledger_index`. The v234.2.5 browser client accidentally read `ledgerIndex`, which produced `NaN` and caused the payment-expiration safety guard to reject every prepared payment with “Prepared payment does not have enough ledger-expiration headroom.”

## Security behavior

- The existing `LastLedgerSequence` expiration safety guard remains enabled.
- The 20-ledger preparation window is unchanged.
- Fresh pre-sign ledger and account-sequence rechecks remain enabled.
- Wallet signing remains local and operation-scoped.
- ATM Town still receives only the already-signed transaction blob for relay.
- Embedded wallet remains XRPL Testnet-only.
- Xaman/Mainnet paths are unchanged.

## Regression validation

The build validator now requires the server to return `ledger_index`, requires the browser to consume `preparedLedger.ledger_index`, and explicitly rejects the obsolete `preparedLedger.ledgerIndex` access.
